GeoXel

From Aerial Video in the Wild

GeoXel reconstructs geographically aligned camera trajectories and dense 3D geometry from long-duration aerial video.

Repository 📄Paper ▶Demo
01 / Abstract

Geographic grounding for long aerial video

Feed-forward geometry models efficiently estimate camera motion and scene structure, but long sequences accumulate drift and do not naturally align with geographic coordinates. GeoXel uses widely available Digital Orthophoto Maps (DOM), Digital Elevation Models (DEM), and OpenStreetMap (OSM) as spatial supervision.

Video is processed as overlapping chunks. Geo-referenced anchors guide segment-local test-time token adaptation while the visual backbone remains frozen. Intra-chunk and global pose-graph optimization then produce a consistent ENU trajectory and per-pixel geographic map.

02 / Method

Stream, ground, refine

GeoXel combines a frozen StreamVGGT visual prior with geographic observations and deterministic trajectory refinement.

01

Frozen forward

Process overlapping video chunks with StreamVGGT and retain the streaming geometry state.

02

Geographic observations

Match image crops to DOM features and use DEM elevations to obtain ENU anchors.

03

Token adaptation

Optimize detached, segment-local aggregator tokens while preserving the frozen backbone.

04

Pose graph refinement

Join intra-chunk and global constraints into a geographically consistent trajectory.

03 / Code

Run the public AMtown entry point

Install the dependencies, prepare UAVScenes and a local StreamVGGT checkpoint, then run the reproducible 200-frame configuration.

UAVSCENES_ROOT=/path/to/uavscene \
CHECKPOINT=/path/to/checkpoints.pth \
bash scripts/run_uavscenes_amtown.sh

The default uses frame index 200, stride 5, 32-frame segments, 8-frame overlap, token adaptation on layers 17 and 23, and pose-graph refinement.
